# 面试讲解手册

> 这份文档不解释代码怎么写，只解决一件事：**怎么在面试里把这个项目讲清楚**。
> 按顺序看完前 3 节即可应对单轮技术面；第 4 节开始是深挖题。

---

## 1. 三句话版本（先背下来）

> 这是一个**企业级后台管理系统的前端工程**，Vue 3 + TypeScript + Vite + Naive UI，包含 11 个业务域、110 个业务路由。
>
> 它的特点是把"没有后端"这件事做成了工程约束而不是妥协：接口契约、分页协议、RBAC、字典、日期格式全部走真实链路，只把网络层换成可复现的本地引擎，所以**换成真后端时页面代码零改动**。
>
> 工程侧有 44 个单测、CI 四道闸门，以及从 CSS 变量到 Naive themeOverrides 的三层设计令牌，改一个主色全站跟随。

## 2. 一分钟版本（面试官说"介绍一下这个项目"）

分四段讲，每段一句，中间留半秒：

1. **背景与定位**：这是我独立完成的一个通用企业管理平台前端，覆盖客户、项目、合同、人事、资产、资金、审批、权限等 11 个域，72 个业务路由全部可用可点。
2. **技术选型**：Vue 3.5 + TS 严格模式 + Vite + Naive UI + Pinia + Vue Router，请求层用 Alova——因为它有适配器机制，这是后面"可演进"的关键。
3. **我做了什么**：做了三件比较有意思的事——顺手写了一层本地数据引擎，让整套业务流在没有后端时也能完整演示；把表格列改成由接口下发，解决后台系统里列配置四处漂移的问题；把视觉收敛成三层设计令牌，换主色不用改组件。
4. **工程习惯**：给最容易回归的三块逻辑（伪随机、字段推断、列生成）写了 44 个单测，配了 CI，`pnpm verify` 一条命令跑完 lint + 类型 + 测试。

## 4. 四个可深挖技术点

面试官通常只会挑一两个深问。每个点的讲法是：**先说问题 → 再说做法 → 最后说取舍**。

### 4.1 没有后端，怎么让业务流完整可跑

**问题**：做个人项目时，通常用 `mockjs` 或者干脆硬编码数据。结果是分页是假的、loading 是假的、错误分支走不到，一接真接口就要重写页面。

**做法**：把 Alova 的适配器接口实现掉，请求不进网络层，而是交给本地分发引擎。

```
页面 → service/api/xxx.ts → alova 实例 → mock/adapter.ts → mock/engine.ts → schema/ + data/
```

三点值得说：

- `adapter.ts` 实现的是 Alova 官方的 `AlovaRequestAdapter` 接口，**不是自己造一层中间件**。所以删掉它、换回 `GlobalFetch`，页面代码一行不用改。
- 引擎按「模块 + 动作」路由（`crm/invoice` + `search`），返回的仍然是 `Promise`。`await` 时序保留 → `pageLoading`、竞态、异常分支都还在真实路径上，这是"能演进成真"的前提。
- 返回结构严格按后端契约：分页是 `Service.ResultPage<T>`（`list` / `total` / `page` / `size`），单条是裸对象，布尔动作返回 bool。契约不是为 mock 设计的，是为真接口设计的。

**取舍**：mock 代码进了生产包（20.6 MB 里有它）。真上线会改成动态 import 或独立 mock 服务，但作为作品集，"打开就能跑"的价值高于包体积。

**代码锚点**：`src/mock/adapter.ts`、`src/mock/engine.ts`

### 4.2 表格列由接口下发

**问题**：后台系统最烦的是表格。列顺序、列宽、对齐、哪些列参与合计、哪些可筛选——如果每个页面自己写死 `columns`，一年后会漂移得没法维护，而且和"页面用了哪些字段"永远对不齐。

**做法**：列不给前端写，由接口下发。

```
dataformat/get?name=atlas/crm/invoice
  → buildColumns('atlas/crm/invoice')
  → resolveModuleDir() 解析到 crm/invoice
  → MODULE_SCHEMA['crm/invoice'].fields
  → 推断类型 / 宽度 / 对齐 / 是否合计
  → DataFormatColumn[]
```

讲这个点时强调三层信息怎么用：

- **第一层，字段从哪来**：`MODULE_SCHEMA` 是脚本从视图代码里静态提取生成的（`pnpm mock:schema`），所以"页面声明了什么字段"和"表格显示什么列"天然一致，不会漏。
- **第二层，怎么解析**：页面传的是完整格式名 `atlas/crm/invoice`，`resolveModuleDir` 剥掉命名空间还原成模块目录——这一步是坑，一开始直接拿原始名查表，覆盖永远不生效。
- **第三层，脏数据怎么办**：有些页面的**表单**字段会污染**列表**（典型是角色页，授权表单的 3 个字段把列表 7 个字段挤掉了）。做法不是去改生成器，而是加一张 `FIELD_OVERRIDES` 覆盖表，按解析后的模块目录登记，**显式覆盖优于隐式猜测**。

**追问「为什么不用后端配置化（低代码那套）」**：低代码把列配置存数据库，灵活但调试困难、类型丢失。这里选的是"编译期提取 + 少量覆盖"，成本低、可 diff、能进 Git review。

**代码锚点**：`src/mock/schema/columns.ts`、`src/mock/schema/schema.generated.ts`

### 4.3 设计令牌三层，换主色不用改组件

**问题**：Naive UI 的 `themeOverrides` 能改组件色，但布局骨架（侧栏、页签、卡片描边）的样式在 Less 里，两边各写一套就会分裂。

**做法**：三层单向依赖。

```
tokens.less    CSS 变量：色板、圆角、阴影、层级、动效（明暗两套值）
     ↑
theme.ts       主色 → 派生色（@ant-design/colors）→ Naive themeOverrides
     ↑
skin.less      布局骨架皮肤：侧栏 / 页签 / 卡片 / 表格
```

关键实现：`theme.ts` 里一个 `watchEffect`，把主色和它的 10% / 16% / 22% 透明版本写进 `--atlas-brand-*`。于是菜单选中态、页签芯片、按钮环、图表全部跟着走，组件里没有任何硬编码色值。

**取舍**：多一层变量意味着改样式时要多想一步"这个值该进令牌还是留在组件"。但收益是**暗色模式不用单独写一遍**——两套值挂在 `html.dark` 上，骨架自动跟随。

**代码锚点**：`src/styles/tokens.less`、`src/styles/skin.less`、`src/store/modules/theme.ts`

### 4.4 RBAC 的前缀匹配与子树校验

**问题**：按钮权限如果只做字符串相等，那配置一个"模块级"权限就得把子权限全列一遍。

**做法**：`matchPermit` 支持两种写法，共用一套权限树。

| 配置 | 用户持有 | 结果 | 语义 |
| --- | --- | --- | --- |
| `CRM_INVOICE` | `CRM_INVOICE_ADD` | ✅ | 配置短码 → 校验整棵子树 |
| `CRM_INVOICE_ADD` | `CRM_INVOICE_ADD` | ✅ | 配置完整码 → 精确命中 |
| `CRM_INVOICE_ADD` | `CRM_INVOICE` | ❌ | 精确码不接受父级降级 |

实现是三步：`findNodeAll` 在权限树里找到所有匹配配置的节点 → `forEach` 把子树 ID 全收进 `Set` → 与用户权限求交集。用 `Set` 而不是数组，是因为权限树可能有几百个节点，交集用哈希查找比 `includes` 稳。

**代码锚点**：`src/utils/permission.ts`、`src/utils/__tests__/permission.spec.ts`

### 4.5 确定性伪随机：让 mock 数据可复现

**问题**：`Math.random()` 生成的 mock 数据，刷新就变，演示时"刚才那一行"找不回来，单测也没法断言。

**做法**：种子 = 模块名 + 行号的哈希（FNV-1a），随机数发生器用 mulberry32。

- 同一页面刷新两次，数据完全一致 → 演示时可以稳定讲解某一行的来龙去脉
- 不同模块种子不同 → 数据不雷同
- 单测能断言具体取值 → 字段推断逻辑真正被覆盖，不是摆设

还有个细节：金额字段做了**勾稽**——`totals` 和 `taxes` 不是各随机一个数，而是 `totals / 1.13 * 0.13`。单据里如果价税合计和税额对不上，懂业务的面试官一眼就看出来。

**代码锚点**：`src/mock/data/random.ts`、`src/mock/data/fieldValue.ts`

## 5. 工程化怎么讲

不要说"我配了 ESLint"，要说**闸门**：

```bash
pnpm verify   # lint + typecheck + unit test
pnpm build    # 生产构建
```

CI（`.github/workflows/ci.yml`）在每次 push / PR 跑同样四步：lint → typecheck → test:run → build，任一步失败即阻断，产物传 artifact。

**为什么只测这三块**（被问"为什么测试这么少"时答）：

> 单测覆盖的不是 UI，是**最容易静默回归的纯函数**——伪随机生成、字段类型推断、列定义组装、权限匹配。这四块出错不会报错，只会让表格某一列悄悄变空，靠人眼点页面发现不了。UI 层用端到端路由巡检兜（110 条路由逐个打开，抓控制台报错和表格空值）。

## 7. 常见追问

**Q：为什么用 Alova 不用 axios？**
A：两个原因。一是它有适配器机制，能替换传输层而不动业务代码——这是我做本地引擎的前提；二是它自带请求缓存和状态管理集成，列表页切页签回来不用重复请求。axios 要自己包一层拦截器才能达到类似效果。

**Q：110 个页面你一个人写完的？**
A：页面是业务形态的重复，不是技术难点。真正的设计在于**把它们收敛成一套抽象**：所有列表页共用 `useListPage`，列从接口下发，查询表单用 schema 声明。所以新增页面的成本是 60 行左右。我在这个项目里更想展示的是抽象能力，不是堆页面的体力。

**Q：类型安全做到什么程度？**
A：TS 严格模式，`any` 在 ESLint 里是 error 级别。接口返回统一用 `Service.ResultPage<T>` 泛型约束，权限树是 `Auth.Permission` 类型，表格列定义有 `DataFormatColumn` 接口。类型不是装饰，是让重构敢动手的前提。

**Q：性能上做了什么？**
A：三处。表格用 vxe-table，虚拟滚动是它默认开的行为，超过阈值自动生效；路由按模块懒加载分包；`KeepAlive` 配合路由的 `meta.keepAlive` 做页签级缓存，切回旧页签不重新请求。剩下的说实话这个项目的数据量还没到需要深度优化的程度，我不会编造性能数字。

**Q：暗色模式怎么做的？**
A：不是覆盖一遍样式，是靠设计令牌。两套值挂在 `html.dark` 和 `html[data-vxe-ui-theme='dark']` 上，Naive 的 `themeOverrides` 走 `darkTheme`，VXETable 单独对齐。骨架样式只写一份，跟随变量走。

**Q：如果接真后端要改多少？**
A：改一个文件。删掉 `mock/adapter.ts` 的注册、换成 `GlobalFetch`，把 `service/api` 里的 URL 前缀对齐真实网关。页面、hooks、组件都不用动——因为从第一天起我写的就不是"假接口"，是**真契约的本地实现**。

**Q：讲一个你发现并修掉的隐蔽 bug。**（这题几乎必问，用一个真实例子最有力）
A：页签缓存一直没生效，但从来没报过错。`<KeepAlive :include>` 装的是路由 name，而它匹配的是**组件自己的 name**——两边的命名在我重构路由时走岔了：路由改成 `CrmProject`，页面里还写着 `TradeProject`。105 个开了 `keepAlive` 的路由里有 93 个对不上，效果是切页签回来表单和筛选全部重置。发现方式不是靠眼睛点页面，是写了个脚本把「路由 name × 组件 name」全量比对，一眼看出 93 个不等。修法是让组件 name 由路由 name 派生（`index.vue` 用路由名，`detail.vue` 用路由名 + Detail），修完 105/105 对齐，再从运行时读 `keepAliveComp` 确认 include 列表就是 `['DashboardOverview','ExpenseBudget',...]`。这类 bug 的价值在于：**它不报错、不影响功能、只损失体验，靠测试也测不出来，只能靠「知道机制长什么样」去查。**

**Q：这个项目最难的地方是什么？**
A：不是写页面，是**让 110 个页面看起来是同一个系统**。做法是先把三件事统一：列表的数据流（一个 Hook）、列的定义（一条链路）、视觉的取值（一套令牌）。这三层统一之后，页面才只是配置。

**Q：有什么没做好的？**（这题一定要有答案，否则不可信）
A：两个。一是 mock 代码打进了生产包，20.6 MB 里有它，真上线要拆成独立 mock 服务或动态 import；二是端到端只做到路由巡检和截图，没写真正的交互断言（比如"点新增 → 填表 → 保存 → 列表多一行"），这块应该用 Playwright 补。

## 8. 五分钟演示动线

别从登录页开始逐个点菜单——面试官会走神。按这个顺序：

1. **登录页**（15 秒）：左右分栏、品牌面板。说一句"登录态和动态路由过滤在守卫里，无权限的路由根本不注册，不是渲染后隐藏"。
2. **工作台**（45 秒）：问候卡 + 我的申请 / 我的审批 / 最新动态三块列表。点任意一条，直接弹出这张单据的详情弹窗（`BizDetailHost` 按业务键懒加载对应 `detail.vue`，不跳路由）。说一句"列表和详情取的是同一条记录，不是两套假数据"；想看图表就点侧栏的运营监控。
3. **打开任意列表页**（60 秒）：这是重头戏。双击行看详情 → 点查询条件 → 切分页 → 说明"列是接口下发的，`dataformat/get` 返回列定义，页面只声明插槽"。
4. **角色/权限页**（45 秒）：展示权限树和 `FIELD_OVERRIDES` 的效果，说明"这里原来表单字段污染了列表，我用覆盖表而不是改生成器"。
5. **切暗色**（30 秒）：一键切换，说明令牌三层，全站跟随。
6. **终端的 `pnpm verify`**（60 秒）：让四道闸门跑一遍，output 自己会说话。

总计约 4 分半，留 30 秒给提问。

## 9. 主动交代边界（诚实反而加分）

在演示结束、或面试官问"还有什么"时，主动说清：

- 这是**纯前端演示版**，无服务端，数据由本地引擎生成；
- 数据是**程序化生成**的，不是真实业务数据；
- 已移除原工程中的所有第三方 SDK、地图、支付、短信等外部依赖；
- 查询式页面（如"工资生成"）首屏为空是**符合业务预期**的——需要先选薪资组才有数据，不是 bug。

主动划边界，比被问出来强。
