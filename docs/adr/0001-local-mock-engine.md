# ADR-0001：用本地 mock 引擎替代后端

- 状态：已采纳
- 日期：2025-11

## 背景

项目是 110 个页面的企业后台。要让它能独立运行、可被任何人 clone 后直接跑起来，
有几条路：

1. 保留后端，让使用者自己起服务 —— 不现实，依赖数据库与内网环境；
2. 用 `json-server` / `msw` 之类的工具挂静态 JSON —— 数据是死的，增删改没有反馈；
3. 用成熟的 mock 方案（Apifox / YApi 导出）—— 仍然需要额外的服务进程。

## 决策

自研一个**运行在浏览器内的 mock 引擎**，作为 Alova 的 `requestAdapter`：

- 拦截全部请求，按「模块 + 动作」分发，返回与后端一致的响应结构；
- 数据由可复现的伪随机算法按字段语义生成，而不是静态 JSON；
- 增删改、导出、打印、树、字典都有对应实现，不是只覆盖列表。

## 为什么不是 msw

msw 走 Service Worker，本质仍是一个 HTTP 服务；本项目需要的是**函数级**替换，
这样才能保证「删掉 mock 层即接回真实后端」时页面代码零改动。
自研 adapter 只依赖 Alova 的一个接口，替换成本一个文件。

## 后果

正面：

- 一个 `pnpm dev` 就能演示完整业务流，包括提交、审批、过账；
- 数据结构与页面字段一一对应，表格不会出现「有列无值」；
- 单测可以直接断言数据生成规则，回归有保障。

负面：

- mock 引擎本身是要维护的代码（约 1.5k 行），字段语义词典需要随业务演进补充；
- 无法验证真实网络的错误码、超时、鉴权刷新等场景（这部分靠 adr 之外的集成测试补）。
